### The session-cache renewal rule

Better Auth's session-cache cookie lives 5 minutes. When it is missing or expired, the proxy
(`proxy.ts`, `renewSessionCache`) reads the session from the database once and sets a fresh
cookie, so the next 5 minutes of that user's page loads read the session from the cookie. The
renewal path therefore runs **at most once per 5 minutes per user**. It is reported as
information, not against the 200 ms read budget. The budgeted read is Home with a fresh
cookie, the path for every other load. The renewal adds about 260 ms (about 4 Neon round trips
inside Better Auth's `getSession`) before the static shell is sent.

## Accepted miss

### Home mobile LCP, 2.8 s against 2.0 s (accepted by the user for M1)

- **Measured:** Home 2.79-2.81 s over three Lighthouse mobile runs, and `/en` (the same page in
  English) 2.79 s. Observed unthrottled LCP is 0.37 s, down from 0.46 s before fixes. The
  static shell paints at 65 ms, and the document stream ends at 154 ms (277 ms before).
- **Why it misses:** the LCP element is the status card's `p.text-2xl` ("You're paid up for
  November 2026"). It streams in after the static shell, so it paints after every first-load
  script has started. Lighthouse's simulation then charges all of the framework JS (about 160 kB
  on slow 4G) to it. Element render delay in `lcp-breakdown-insight`: 355 ms observed.
- **Decision:** the user accepted this miss for M1 on 2026-11-03. The real-user number is
  rechecked with Vercel Speed Insights in M7.

## Remaining misses

### 1. Mobile LCP on More (2.79 s) and Profile (2.64 s) (Must fix, or extend the acceptance)

- **Status:** the same mechanism as Home. More's LCP element is the building address in the top
  bar (`header … p.truncate`), and Profile's is the email (`dl … dd.font-medium`). Both are
  streamed, and the observed render delay is 338-350 ms. The acceptance above names Home. These
  two pages miss the same budget for the same reason, so they need a fix or the same written
  acceptance.
- **Regression on More (+0.23 s) and Profile (+0.08 s):** the observed LCP is unchanged (More
  341 → 347 ms, Profile 352 → 359 ms). The only new request on these pages is the preloaded Rubik
  `latin-ext` file (`9d760601823f9ac2-s.p….woff2`, 19.6 kB), which `app/ui/fonts.ts:8` now
  preloads on every route. Lighthouse's simulation puts it on the critical path. These pages
  show no ₪, so the preload buys them nothing.
- **Fix, by impact:** (a) render the LCP text in the static shell. The top bar's building
  address and Profile's email both depend on the session, so this requires the shell to take a
  name-sized placeholder so the streamed text is smaller than an element the shell already
  paints. Alternatively, make the page heading (static) the largest element. (b) Preload
  `latin-ext` only where ₪ is shown. One way is a second `next/font` Rubik instance with
  `subsets: ['latin-ext']` imported only by the Home status card, keeping `hebrew` and `latin`
  preloaded globally. This should bring More back to about 2.56 s. It is not enough to pass on
  its own.
